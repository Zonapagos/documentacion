## Formularios configurables

El comercio puede diseñar la experiencia de captura de información definiendo:

- Descripción del formulario.
- Cantidad de campos.
- Tipo de campo.
- Información que deberá diligenciar el usuario.

## Campos disponibles
| Campo                   | Descripción                                                                                                                                                                                                                                  |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Descripción del pago    | Concepto o detalle del producto o servicio. Puede ser **predefinido por el comercio** mediante una lista de opciones o configurarse como un **campo abierto** para que el usuario final diligencie el valor manualmente.                     |
| Valor a pagar           | Valor asociado a la transacción. Puede ser **ingresado por el usuario** o **autocompletarse automáticamente según el concepto seleccionado en la Descripción del pago**, cuando exista una relación previamente configurada por el comercio. |
| Documento del comprador | Documento de identificación del cliente.                                                                                                                                                                                                     |
| Nombre completo         | Nombre del pagador.                                                                                                                                                                                                                          |
| Número celular          | Información de contacto del cliente.                                                                                                                                                                                                         |
| Correo electrónico      | Dirección de correo del cliente.                                                                                                                                                                                                             |

<Note> Nota: Todos los campos son diligenciados por el usuario final durante el proceso de recaudo. Dependiendo de la configuración definida por el comercio, algunos campos pueden mostrarse 
preconfigurados, condicionados o autocompletados </Note>
<Note> Ejemplo de configuración: El comercio puede definir una lista de conceptos (por ejemplo: Certificados, Inscripciones, Membresías) donde cada opción tenga un valor asociado. Cuando el 
usuario selecciona un concepto, el sistema completa automáticamente el Valor a pagar correspondiente antes de redirigir al portal de pagos. </Note>

## Tipos de componentes soportados

Zonaexpress soporta diferentes tipos de componentes para construir formularios adaptados al proceso de recaudo:

- Campo texto corto.
- Campo texto largo.
- Lista desplegable.
- Selección única.
- Selección múltiple.

## Personalización de la taquilla de pagos

La experiencia visual del portal de recaudo es configurada por el equipo de Zonapagos para garantizar consistencia visual y correcta operación del flujo transaccional.

### Capacidades de personalización

- Incorporación del logo del comercio.
- Parametrización de campos.
- Configuración de colores corporativos.
- Experiencia alineada con la identidad visual del comercio.

<Check> Importante: La configuración de la taquilla de pagos es realizada directamente por el equipo de Zonapagos. </Check>

## Compartir el portal

Una vez finalizada la configuración:

- Se genera una URL única para el formulario.
- El comercio comparte esta dirección con sus clientes.
- La URL permanece constante para todos los pagadores.

Este modelo facilita la distribución del canal de recaudo y elimina la necesidad de generar enlaces individuales.

## Redirección al pago

Después del diligenciamiento del formulario:

- El usuario es dirigido automáticamente al portal de pagos.
- Selecciona el método de pago disponible.
- Completa la transacción.

El proceso mantiene continuidad entre la captura de información y el recaudo, evitando pasos adicionales para el usuario final.

## Beneficios

- Implementación rápida.
- Sin necesidad de base de facturas.
- Construcción de base de datos propia.
- Mayor flexibilidad en captura de información.
- Experiencia personalizada.
- Proceso seguro de recaudo.

## Consideraciones

Para garantizar una mejor experiencia de recaudo, se recomienda:

- Definir únicamente los campos estrictamente necesarios.
- Mantener formularios simples y fáciles de diligenciar.
- Validar previamente la experiencia del usuario antes de publicar el formulario.
- Garantizar que la información recolectada cumpla con las políticas de tratamiento y protección de datos aplicables.
